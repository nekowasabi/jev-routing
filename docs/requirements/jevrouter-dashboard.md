# Jevの稼働と節約効果を示すダッシュボード

## 目的

Jevに詳しくない利用者が、同じ画面で次の問いに答えられるようにする。

1. どのエージェントの、どの処理でJevが使われたか。
2. Jevを使わなかったのは正常な省略か、無効設定・未対応・障害か。
3. Jevの判断が実際の操作につながったか。判断しただけで止まっていないか。
4. Jev自身にどれだけトークンと時間を使ったか。
5. その負担を含めても、同じ仕事を少ない総トークン・短い時間で終えられたか。

今回の範囲は計画への追加であり、画面実装・実測比較は未実施。[自動接続仕様](jevrouter-host-integration.md)の判断・配達・実行・結果の識別子をそのまま可視化へ使う。既存のHTML／JavaScript画面、Goの配信・イベント、比較集計器を拡張し、別の管理サービスやフロントエンド基盤は追加しない。

専門用語は補助表示に置く。「Jevへ相談」「ローカルで確定」「過去の判断を再利用」「判断したが未適用」「権限待ち」「結果が未確認」など、何が起きたかを主表示にする。

| 未適用の理由 | 無効設定／未対応／低確信／API失敗／時間切れ／予算超過／適用不一致等の横棒 | 問題箇所と原因。意図的な未使用と障害を区別 |

スキル本文の配達はスキル遵守の証明ではなく、子の起動は子の成果の証明ではない。種類ごとの証拠が違うため、該当しない段階は「対象外」として表示する。未呼出し、未接続、計測範囲外は別ラベルにする。通信が観測されていないだけのホストを「Jev無効」と断定しない。

選定元と適用状態は別軸にする。例えば「Jev判断・未適用」と「ローカル判断・適用済み」の双方を表現する。全件数の割合を表示するときは、分子／分母と対象範囲をクリックで確認できるようにする。

## 指標の計算契約

### 総トークンとJev使用量

- `総トークン = 親LLMの正規化済み入出力 + 子LLMの正規化済み入出力 + 全Jev要求の入出力`。親・子の同一API要求を複数の観測経路で重複加算しない。
- `Jev使用量 = 実際の全HTTP試行の報告済みusage合計`。選定だけでなく履歴圧縮・モデル・委譲・分割・再試行も含む。Jev側がusageを返さなかった失敗試行は0扱いせず欠測を残す。
- 判断キャッシュ命中は、新しいJev要求が発生していなければ当該要求分の使用量は0。キャッシュ内の過去usageを再加算しない。過去の呼出しは過去の発生時点にだけ計上する。
- プロバイダーごとに入力総量へキャッシュ読取り／書込みが含まれるかを確認して正規化する。出力内訳の推論トークンを出力総量へ再加算しない。元のusageと正規化規約を残す。
- 一要求で複数分類を判断した場合は共有のJev使用量として一度だけ計上する。分類ごとに同じ全量を足さない。正確に帰属できない量は「複数処理で共有」とする。
- 未観測の子、独自通信でusageを取り出せない応答等は欠測数と観測範囲を示す。分かっている小計は表示できるが、全体の確定値や純削減率は表示しない。

### 節約の表示

比較条件が一致し、同じ外部成功条件を満たす対照とJev利用の実行を対応付ける。

`削減トークン = 対照の総トークン − Jev利用時の総トークン`

`削減率 = 削減トークン ÷ 対照の総トークン`

対照が0、欠測、未実行、品質不合格、比較条件不一致なら率は算出しない。正・負の差分を切り捨てず表示する。対照は同じタスク・入力・履歴・能力版・ホスト・成功条件を固定した実行とする。モデル自動選択の比較ではモデル変更が介入であることを表示し、ルーティング単独の効果と混同しない。

失敗・再試行に使ったトークンも完了までの総量に含める。成功例だけを抽出して節約を過大表示しない。完了しなかった実行は失敗として使用量と時間を残し、成功実行の節約として採用しない。反復比較は組の件数、総量、中央値・ばらつきを表示し、単発実測を一般的な改善保証にしない。

既存の文字数に基づく入力削減は「推定」、APIのusageは「実測」、比較未成立は「未判定」と常時区別する。`削減推定 + 実測削減`のような二重加算はしない。トークン量を料金と同一視せず、料金表示を追加するなら出典・適用日・モデル別単価が揃ったときだけ別計算する。初期版の主指標はトークンと時間である。

### 時間の表示

タスク完了時間は親の開始から必要な子・ツール結果と成果確認が揃うまでの壁時計時間とする。`短縮時間 = 対照の完了時間 − Jev利用時の完了時間`。未完了は経過時間として表示し、完了時間比較へ混ぜない。

Jevの各試行時間とその累計は「Jev呼出し時間」であり、タスク完了時間とは別指標。並列呼出し・子エージェントの時間を足してタスク完了時間としない。直列区間は内訳を表示できるが、重複区間はタイムラインで表し、単純な積み上げ時間にしない。別端末の時計差で厳密に位置付けられない場合は、親側の送受信境界と計測上の制限を表示する。

## 計測と配信

データを持つ境界で記録する。Jev HTTP試行は`internal/jev`の既存フック、LLM usageはプロキシ応答、操作適用は接続処理、子起動・返信はateamから取得する。画面側でログ本文を推測して成功や節約を作らない。

共通項目は`run_id / parent_run_id / decision_id / call_id / attempt_id`、ホスト、分類、判断元、適用状態、開始・終了、usageと欠測理由、能力・方針の版。選定イベントの更新は同一IDの置換として扱い、ポーリングやSSE再接続で二重加算しない。

既存のイベントAPIへ期間集計と比較結果を追加する。詳細履歴は上限付きのまま、期間集計は集計済みの時系列区間と累計から返す。画面の表示件数制限が総使用量を変えないようにする。保持期間外、サーバー再起動、ログ欠落は明示する。過去比較は保存済み実行統計と既存Python集計器の派生出力から読み込み、集計JSONを手で編集しない。模擬データを実測比較として読み込ませない。

トークンが後から届く更新、同じusageの累積通知、集計対象フィルターの変更にも対応する。親子を含む全体と単一ホストの表示を切り替えた際に、集計範囲・期間・未計測数も一緒に切り替える。画面更新が止まったら最終更新時刻と「接続切れ」を示し、古い状態を「現在正常」と表示しない。

本文・引数・認証情報・スキル全文は指標画面へ送らない。詳細はID、能力名、理由コード、時間と量を中心にし、既存のローカルアクセス制限を維持する。

## 実装と受入

グラフは既存のJavaScriptとSVG／CSSを優先する。新しいグラフ基盤が不可欠でない限り依存を増やさない。色だけに頼らず、凡例・数値・日本語ラベル・同じデータの表を用意する。キーボードで対象を切り替えられ、画面幅が狭い場合も要約カードと警告が読めること。

工程09で集計・比較API、工程10で画面・グラフを実装する。両工程で以下を検証する。

- 実測、推定、欠測、比較なし、改善、悪化、品質失敗を固定データで描画し、期待値と一致させる。
- 複数質問の共有usage、キャッシュ、再試行、親子二重観測、履歴上限、途中更新、再接続で合計が変わらないこと。
- 並列実行の合計時間を壁時計短縮として表示しないこと。終了していない処理を完了扱いしないこと。
- ローカル確定を障害として表示せず、Jev選定後の未適用は正常として隠さないこと。
- 通信がないホスト、未知usage、模擬比較を「節約できた」と表示しないこと。
- ブラウザーで各グラフ・絞込み・詳細表示・再接続を確認する。DOM上の値だけでなく画面の欠け、凡例、欠測表示、読上げ用の表も確認する。
- Jevに詳しくない利用者向けの受入課題として、用語解説を開かずに「どこで使ったか」「使わない理由」「Jev使用量」「総トークンの増減」「時間の増減」を画面内で識別できることを確認する。
